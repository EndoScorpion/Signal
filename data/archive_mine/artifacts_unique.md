Registry mechanism (clone control / self-improvement):

## NEW and worth adopting (ranked by expected value)

1. **Automatic worst-neighbour + shuffled-entry control as promotion gate** (artifact 1, 5). Expected value highest: it directly targets curve-fit (21+ candidates tested per batch, OOS losses on every GEN1 year). Implementation (loop rule): in auto_loop.py, after a candidate passes the WIN rule, auto-queue its +-20% and +-1-step neighbours for each numeric gate input and a shuffled-entry replay (same trade count, random entry times, same exits); promote only if the WORST neighbour keeps the same sign and the real result beats the shuffled mean by a margin. Log "worst_nb" and "shuf_mean" in TEST_LOG.
2. **Day-block bootstrap p-value with Bonferroni-style alpha for the batch** (artifacts 2a, 3). Implementation (loop rule): compute p(net <= 0) by resampling trading days (data/dsr_check.py can host it) and require p <= 0.05 / N_candidates_in_batch (artifact used 0.0024 for 21) on pooled unseen-year days before any candidate is called a WIN; a candidate that only passes in-sample is labelled "needs OOS".
3. **EntryDelaySec (5 s) and hard open-order cap as optional EA gates** (artifacts 1, 2a). Entry delay improved the old ladder every year (+6..+53 pts/yr-sum) with no fragility; hard 4-order cap (g2e) was queued and never tested. Implementation (optional EA gate): `EntryDelaySec` input (default 0, variants 0/5/15) delaying order placement after the signal bar, plus `MaxOpenOrders` (default off) in the MR_RegimeSwitch order loop; add both as one-change candidates `d_delay5`, `d_cap4`.
4. **Cost-aware gate (CostGateOK): require (tp - cost)/(sl + cost) above breakeven, and TP >= breakeven pts** (artifact 3). The old repo had this as a no-op bug (tp/cost ~37); the right formula blocks trades whose payoff cannot clear spread + 8 pt commission. Implementation (optional EA gate): `UseCostGate`: skip entry when (tp_pts - cost_pts)/(sl_pts + cost_pts) < breakeven ratio implied by the candidate's measured win rate (leader: payoff 1.67, breakeven win 37.5%); raise TP together with it so trades are not all filtered.
5. **Identical-trade-list clone dedupe + plateau stop** (artifacts 1, 5). Implementation (loop rule): hash each finished report's entry timestamps; if hash equals an existing report, mark the new candidate "clone of X", skip further test years, and do not count it toward the plateau counter. Stop the pass after 2 consecutive generations with no new OOS winner (100+ trades net of 8 pt) and write the hash table to LINEAGE_DNA.md.
6. **Sells-only / per-side attribution column per report** (artifacts 1, 4b). Buys lost -44..-140 per year while sells won; MR_RegimeSwitch clones are mostly sell-only now but b55 buy rules are queued. Implementation (dashboard feature / loop rule): in the report parser store net, trades, win% separately for buys and sells and rank clones on each side; kill a side gate that loses in 3 of 4 unseen years instead of the whole clone.
7. **Replay-before-test for TP/SL and exit changes** (artifact 2a: TP200/SL400 replay lifted PF 1.13 -> 1.28 on stored fills). Implementation (loop rule): for exit-only ideas (n_exit_tp600, n_trail100_150, ATR caps) replay stored fill prices offline first and send only the top replays to the tester, saving tester runs (matches RAM/one-test-at-a-time limits).
