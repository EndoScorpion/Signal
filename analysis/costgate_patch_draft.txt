## BUG DESCRIPTION

Current code (Strong2010b_claude.mq4, CostGateOK):

    double rr = (double)tp_pts / MathMax(total_cost, 1.0);
    if (rr < InpMinRR) return false;

With tp=300, total_cost=10 (spread 2pt + commission 8pt):
    rr = 300 / 10 = 30.0  -->  always >= InpMinRR (1.5)  --> gate is a NO-OP

This means the gate NEVER blocks an order based on R:R. It only blocks
if tp_pts <= total_cost (i.e. TP would be eaten entirely by cost), which
almost never happens at tp=300.

## CORRECT FORMULA

Net R:R should be: (tp - cost) / (sl + cost)
  - Numerator: what you actually win after paying cost on the win side
  - Denominator: what you actually lose including cost on the loss side

Fixed code:

    if (sl_pts > 0 && InpMinRR > 0.0) {
        double rr = ((double)tp_pts - total_cost) / MathMax((double)sl_pts + total_cost, 1.0);
        if (rr < InpMinRR) return false;
    }

## TP MINIMUM REQUIRED

With sl=290pt, total_cost=10pt, InpMinRR=1.5:
    TP_min = InpMinRR * (sl + cost) + cost
           = 1.5 * (290 + 10) + 10
           = 1.5 * 300 + 10
           = 460 pt

Knowledge base says >= 458pt (slight rounding diff — use 460 to be safe).

Current InpTPRange=300, InpTPTrend=360 are BOTH below this minimum.
After fix, orders with these TPs will always be blocked by CostGateOK.

## VERIFICATION MATH

After fix with tp=300, sl=290, cost=10:
    rr = (300 - 10) / (290 + 10) = 290 / 300 = 0.967  --> blocked (correct)
